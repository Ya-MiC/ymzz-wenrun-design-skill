# 08 · 跨語言協作——前端心疼後端

> 你指定：「考慮後續 Rust 和 Python 和 Vue 和 JS 各種語言的前端的 skill，前端心疼後端寫的」。本包的語言分工與契約原則。

## 1. 語言分工【已確認架構】

| 層 | 語言 | 職責 |
|---|---|---|
| 界面 | Vue 3 + TypeScript | 全部 UI、狀態（Pinia）、動效、熱區、浮層 |
| 殼 | Rust（Tauri） | 窗口、IPC、文件系統、加密、平台能力、sidecar 管理 |
| 計算/工具 | Python（sidecar，可選） | 重計算、現成庫復用；經 Tauri sidecar 機制啟停 |

原則：**界面邏輯只在 Vue；系統能力只在 Rust；Python 永遠是可替換的計算後端**。任何一層想伸手到另一層的內部實現，都是違規。

## 2. 契約先行（前端心疼後端的核心）

1. **IPC 契約**：每個 `invoke()` 命令有明確的輸入/輸出/錯誤三段 TypeScript 類型，與 Rust 側 serde 結構一一對應，集中在 `src-tauri/src/commands.rs` + `src/api/tauri.ts` 兩個文件。改契約必須同時改兩邊並升版本號。
2. **錯誤是數據不是驚喜**：Rust 返回 `Result<T, AppError>`，`AppError` 帶穩定錯誤碼；Vue 側按錯誤碼映射用戶文案。前端不 try-catch 完事就不管，後端不返回裸字符串錯誤。
3. **邊界校驗雙份**：前端校驗是體驗（即時反饋），Rust 校驗是安全（不信任前端）。兩份都要有，前端的善良不能代替後端的警惕。
4. **異步禮貌**：Rust 長任務必須支持取消與進度事件（`emit`）；Vue 發起前先確認能力存在，不發「後端根本沒實現」的調用。
5. **Python sidecar 協議**：stdout JSON Lines 一問一答；啟動失敗、版本不匹配、意外退出各有明確的用戶文案與降級路徑（功能禁用而非整個應用報錯）。

## 3. 前端 Skill 的語言注意點

- Vue SFC 一律 `<script setup lang="ts">`；組件命名 PascalCase；組合式函數 `use*`。
- 設計 token 是唯一真相源：`tokens/tokens.css` 定義變量，組件**只准消費變量**，禁止散落 magic number（色值、時長、熱區尺寸）。
- 數字展示組件強制 `tabular-nums`（見 02 文檔）——這種鐵律放在工具函數/全局樣式，不靠每個開發者記憶。
- TypeScript 嚴格模式開啟；`any` 需註釋理由。

## 4. 後端（Rust）Skill 的注意點

- 所有 IPC 命令冪等或明確標註非冪等；文件操作先寫臨時文件再原子替換。
- 加密只在 Rust 側做（Argon2id + AES-GCM，`argon2`/`aes-gcm` crates 均雙授權 MIT/Apache 可商用）；前端只拿結果，不碰密鑰。
- panic 不許穿透到 IPC 邊界；捕獲轉 `AppError`。

## 5. 驗收清單（協作層）

- [ ] 每個 IPC 命令有類型契約且兩側對齊
- [ ] 每個錯誤碼有用戶文案映射
- [ ] 長任務有取消 + 進度 + 恢復
- [ ] 前後端各有一份輸入校驗
- [ ] token 變量覆蓋率 100%（組件樣式無 magic 色值/時長）
